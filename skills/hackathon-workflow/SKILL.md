# 실무형 AI 해커톤 작업 흐름

사용자가 문제를 이해하고 판단을 내리도록 돕는다. 시험 안내와 과제 README가 이 스킬보다 우선한다. 확인한 사실, 추정, 실제로 검증한 결과를 구분한다. 제한 시간은 화면과 최신 안내를 기준으로 한다.

## 과제 시작

1. README와 제공된 데이터, 기존 코드, 실행·제출 조건을 살핀다. 필요한 파일만 읽고 필수 결과물과 제약을 짧게 정리한다. 제공된 원본을 변경해야 한다고 가정하지 않는다.
2. 문제를 누가 언제 겪는지, 성공을 어떻게 판단할지, 데이터와 보안 제약이 무엇인지 확인한다. 확인되지 않은 사항은 가정으로 표시한다. 숫자로 측정할 수 있다면 기준과 현재값을 확인하되 없는 수치를 만들어내지 않는다.
3. 모호한 업무 맥락은 사용자가 실무자에게 질문할 수 있게 짧고 구체적인 질문을 제안한다. 실무자와의 대화를 직접 볼 수 없다면 답을 전달받아 반영한다. 도구 사용·제출 절차나 장애는 실제 화면에 제공된 안내 및 신고 경로를 따른다.
4. 남은 시간을 고려해 필수 기능과 확인 방법을 우선순위로 제안한다. 기능이나 의존성을 더하기 전에 기존 환경으로 해결할 수 있는지 살핀다.

## 구현과 확인

- 하나의 핵심 사용자 동작을 작게 완성하고 실제 데이터나 대표 사례로 확인한 뒤 다음 범위를 진행한다. 계산·집계 결과는 근거와 함께 확인하고, 빈 데이터·잘못된 입력·실패 시 화면도 필요한 범위에서 점검한다.
- 실제 요구와 맞지 않거나 데이터로 목표를 달성할 수 없다면 임의로 우회하지 않는다. 확인된 한계와 선택지를 사용자에게 설명하고 필요한 질문을 정리한다.
- 변경과 판단의 이유, 확인한 동작, 남은 한계를 과제에서 지정한 문서에 기록한다. 문서 형식이 정해지지 않았다면 필요한 만큼만 작성한다. 사용자의 개인 메모나 출제자가 제공한 문서를 임의로 덮어쓰지 않는다.
- 웹 화면이 필요하면 제공된 Browser 미리보기에서 실제 포트와 경로를 확인하고 핵심 동작을 직접 점검하도록 안내한다. Cofa Probe 안내는 서버를 `0.0.0.0`에 바인딩하도록 한다. 연결이 안 되면 서버 상태, 포트, 바인딩과 경로를 순서대로 확인한다. `localhost`에서 성공한 것만으로 사용자 화면의 동작을 단정하지 않는다.
- Vite에서 호스트 차단 오류가 확인되면 실제 미리보기 호스트와 Vite의 `server.allowedHosts` 설정을 확인한다. 필요한 호스트만 허용하고 모든 호스트를 허용하는 설정으로 우회하지 않는다.
- 시간과 환경의 자원을 고려해 필요한 프로세스만 실행한다. 플랫폼 설정이나 감독 연결을 변경하거나 제한을 우회하지 않는다. 작업 내용·데이터·결과물의 외부 전송과 Git push는 안내된 제한을 따른다.

## 제출 전

- 지정된 파일, 저장 상태, 실행 방법, 핵심 동작과 미확인 사항을 확인한다. 실무자에게 보여줄 요약이 필요하면 목적, 동작, 확인 결과와 한계를 쉬운 말로 작성하되 측정하지 않은 수치를 넣지 않는다.
- 사용자가 구현 이유, 데이터 흐름, 검증 결과와 한계를 자기 말로 설명할 수 있게 제출 전 정리를 돕는다. 후속 서술형이 시작되면 행사 규칙에 따라 AI를 사용하지 않는다.
- 제출 미리보기에 보이지 않는 파일이 실제 제출 대상에서 제외된다고 가정하지 않는다. 화면과 과제 안내를 확인하고 최종 제출 완료 표시를 기다린다.

이 흐름은 [keepdev0919/hynix](https://github.com/keepdev0919/hynix)의 작업 규칙·맥락 정리에서 아이디어를 얻어 작성했다. 해당 저장소의 후기 기반 주장이나 특정 설정을 행사 공식 규칙으로 취급하지 않는다. 2026년 SK하이닉스 안내 PDF에서는 Cofa Helper와 실무자 에이전트의 역할, Browser 미리보기, 외부 전송 제한 및 서술형 규칙을 확인했다. 실제 응시에서는 최신 안내가 우선이다.
