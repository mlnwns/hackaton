# 데이터 계약과 해석 기준

대시보드의 예쁜 숫자보다 집계 정의가 먼저다. 과제에서 지표 정의를 주면 그 정의를 우선한다. 아래는 일반적인 설계 체크와 예제의 정의이며 SK하이닉스의 내부 운영 지표가 아니다.

## 데이터 계약을 짧게 적는다

- **grain**: 한 행이 관측/검사/LOT/장비-시간 구간 중 무엇인지. primary key와 중복 제거 기준.
- **시간**: event time/수집 time, 원본 시간대, 표시 시간대, 조회 시작 포함·종료 제외 여부. 예제는 KST 날짜 문자열, 일별 양끝 포함.
- **측정**: 단위, 합계/비율/평균/분위수 구분, 분자·분모, 유효 범위.
- **품질**: null/NaN/0, 재검사·취소·중복·부분 집계, 포함·제외 기준과 표본 수.
- **계보**: 데이터 출처, 기준 시각, 집계 버전, 필터 범위. mock·추정·관측을 구분.

## 지표 선택과 함정

| 지표 | 정의를 확인할 점 | 잘못 만들기 쉬운 계산 |
|---|---|---|
| 검사 합격률/수율 | 합격 단위÷검사/투입 단위; 제품·die·wafer·LOT·검사 건 중 하나를 명시 | 표본 수가 다른 LOT의 %를 단순 평균; 검사 단계들을 더하고 최종 제품 수율로 표시 |
| FPY/재검사 | 최초 통과인지, 재작업 후 통과를 포함하는지 | 최종 합격률을 FPY라고 부름 |
| 불합격 수/불량 건수 | 불합격 단위 수와 결함 발생 건수는 다름; 한 제품에 여러 결함 가능 | 결함 건수 합계를 불합격 제품 수로 사용 |
| 처리량/리드타임 | 완료 수/단위 시간, 시작·완료 event, 대기 포함 여부 | 공정 간 중복된 LOT를 신규 생산량으로 합산 |
| 가동률/OEE | 가동률 분모가 계획 시간인지 달력 시간인지; OEE는 별도 availability/performance/quality 정의 필요 | 가동률 하나를 OEE라고 표시 |
| 정지 시간/MTBF/MTTR | 겹치는 정지 구간, 고장 정의, 관측 시간, 완료되지 않은 수리 처리 | 중첩 정지를 이중 합산; 고장 0개를 MTBF=0으로 표시 |
| 에너지 | kW(전력)와 kWh(전력량), 시간 구간, 제품당 분모 | 전력 값을 그냥 더해 전력량으로 표시 |
| p95/평균/통계 | 원본 표본 또는 병합 가능한 분포 요약 필요 | 일별 p95를 평균내 전체 p95라고 표시 |

%는 비율, %p는 비율의 차이다. 98%→99%는 +1%p이며 상대 변화는 약 +1.02%. 표시에서 반올림하되 집계 중간값은 반올림하지 않는다. 분모 0/미관측은 `—`, 정상적인 관측값 0은 `0`으로 구분한다.

## 가중 집계

예: 10건 중 5건 합격, 90건 중 90건 합격이면 전체는 **95/100=95%**다. `(50%+100%)/2=75%`가 아니다. 결측 분자는 그 행의 분모와 함께 집계에서 제외하고 제외 표본 수를 드러낸다. 서로 다른 단위/제품군은 요청한 정의 없이 합치지 않는다.

이 starter의 aggregate는 유효한 `(passed, inspected)` 쌍과 `(runMinutes, plannedMinutes)` 쌍만 사용한다. 유효 쌍이 없으면 비율은 null이다. 온도 결측은 scatter/histogram에서 제외하며 원본 표에는 `—`로 남긴다.

## 비교 기간 / 필터 / 분포

기간 길이·시간대·공정·제품 범위를 맞춘 뒤 비교한다. 7일 합계와 14일 합계를 개선/악화로 바로 비교하지 않는다. 시간 차트는 기준 시간축을 먼저 만들고 관측이 없는 시간은 null로 유지한다. 배열 위치만 같다고 서로 다른 날짜의 값을 비교하지 않는다.

histogram의 구간 경계는 비교 대상에 동일하게 적용한다. 경계값은 한 구간에만 포함하고 마지막 상한 포함 여부를 정한다. 범위 밖 표본은 누락시키지 말고 별도 overflow bin/표본 수를 표시한다. 현재 demo의 합성 온도 편차는 전체가 설정 범위 안에 있다.

Pareto: 유형은 집계 기준상 겹치지 않는지 확인. 다중 결함이면 '결함 발생 건수'로 명시한다. 예제는 검사 불합격 1건에 대표 유형 1개를 부여하므로 유형 합계와 KPI 불합격 수가 같다.

## 공정 관리도와 모델 결과

목표선·제품 규격(USL/LSL)과 통계적 관리한계(UCL/LCL)는 다르다. 관리한계는 변동의 통계적 상태를, 규격은 요구사항 충족을 다루며 같은 선으로 취급하지 않는다. [NIST 설명](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc32.htm)

연속 측정값/불합격 비율/결함 개수는 관측과 표본 구조가 다르다. I-MR, X̄-R/S, p/np, c/u, EWMA 등은 데이터 구조와 목적에 따라 고른다. [NIST 관리도 분류](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc3.htm)

구현 시 baseline 기간·표본군·추정 방법·규칙 버전을 기록한다. 화면 필터가 바뀔 때마다 현재 데이터로 한계를 재학습해 이상을 지우지 않는다. 표본 부족/불안정 baseline이면 그 한계를 밝힌다. 이 demo의 98.5%는 임의의 목표이며 통계 관리한계가 아니다.

모델이 있다면 '관측값/예측값/예측 구간', 모델 기준 시각, 단위, 적용 대상과 제외 범위를 구분한다. 이상 점수≠고장 확률이며, threshold 근거 없이 정상/불량 확정으로 표시하지 않는다. 원인 후보·상관관계·실험으로 확인한 원인을 구분한다.

## 검증 시나리오

1. 합계 일치: 원본 표→KPI→일별 집계의 분자·분모가 일치하는가? 재검사/중복은 정의대로 처리됐는가?
2. 경계: null, 0분모, NaN, 잘못된 범위, histogram 경계값과 기간 첫/마지막 날.
3. 연동: 기간/라인/공정 변경, 차트→원본 기록, 조건 초기화, 페이지 번호 복귀.
4. 표시: 단위/%p/기준 시각, 툴팁 소수점, 빈/실패/지연/결측 상태, 폰트와 반응형.
5. 설명: 클릭 없이 데이터 표로 접근 가능한가? 모의 데이터/추정치/실측치를 사용자가 구별할 수 있는가?

단순 CSS 변경에 집계 테스트를 추가할 필요는 없다. 계산·범위·집계를 바꿨다면 위 불변식을 실제 값으로 검증한다.
