# 원티드 스타일 데이터 대시보드

## 출처 경계

2026-10-31 [Montage 공개 컴포넌트 목록](https://montage.wanted.co.kr/docs/components)을 확인했다. 공식 Select/Table/Tab/Modal 등을 사용할 수 있지만 전용 차트 카탈로그는 이 목록에서 확인하지 못했다. 원티드의 비공개 관리자/분석 화면을 관찰했다는 뜻이 아니다.

이 문서의 **대시보드 배치·KPI·차트 테마는 독립 설계**다. 공개 Montage의 색·타이포그래피, 이전 PC 웹 관찰을 바탕으로 데이터 화면에 적용한다. '원티드 공식 차트 토큰', 'SK하이닉스 내부 화면', '예상 출제 확정'이라고 표현하지 않는다.

## 먼저 사용자의 판단을 정한다

'지금 상태가 어떤가 / 무엇이 변했나 / 어디서 발생했나 / 어떤 기록을 확인할까' 중 화면의 주 질문을 정한다. 보유 데이터에 답할 수 있는 지표만 놓는다. 데이터가 없는 OEE·예지보전 점수·비용 절감액을 장식용 숫자로 만들지 않는다.

| 화면 유형 | 핵심 지표 후보 | 기본 구성 | 상세로 이어지는 행동 |
|---|---|---|---|
| 운영 현황 | 처리량, 검사 합격률, 진행 중 작업, 지연 건수 | KPI 줄 + 시간 추이 + 구역/공정 비교 | 날짜·라인 선택 → 기록 |
| 품질 분석 | 불합격률, 대표 불량 건수, 관측 분포 | 파레토 + 히트맵 + 산점도/분포 | 유형/셀/점 선택 → LOT·관측 |
| 설비 상태 | 가동 시간, 정지 시간, 알람, 점검 대기 | 상태 목록 + 시간선 + 설비별 비교 | 설비 → 이벤트 → 조치 기록 |
| 생산·물류 흐름 | WIP, 처리량, 리드타임, 병목 대기 | 공정별 막대 + 추이 + 작업 표 | 공정 → 대기 작업 → 일정 |
| 에너지·자원 | 전력량, 피크 전력, 단위 생산당 소비 | 시간 추이 + 설비 비교 + 목표 대비 | 기간·설비 → 소비 내역 |

사용자가 반도체 외 주제를 주면 이 구조를 주문/배송/교육/예약/운영 지표로 옮긴다. 핵심 행동과 단위가 먼저이며 '반도체' 문구만 바꾸는 템플릿으로 고정하지 않는다.

## PC 레이아웃 레시피

1. 상단 60px 내비게이션과 좌우 5% 콘텐츠 여백을 기반으로 한다. 데이터 대시보드는 읽기 밀도를 고려해 max-width 1280~1400px 안에서 선택한다. 이 상한은 응용값이다.
2. 제목 아래 **기간·시간대·조직/라인·공정 필터**를 한 줄로 두고, 선택 범위·데이터 기준 시각을 표시한다. 새로고침 시각과 실제 데이터 수집 시각은 별개다.
3. KPI는 기본 3~4개를 얇은 세로 구분선으로 묶는다. 각 숫자에 단위·분모/정의·비교 기간을 연결한다. KPI마다 큰 그림자 카드를 만들 필요가 없다.
4. 첫 분석 줄에 핵심 추이와 비교/원인 후보 차트를 둔다. 너비 비율 7:5 또는 1:1, gap 20~24px, 차트 높이 240~320px을 출발점으로 삼는다. 관련 없는 차트 10개를 한 화면에 쌓지 않는다.
5. 별도 탭/아래 영역에 분포·상관 분석과 원본 표를 둔다. 범위를 좁혀 상세로 이동할 때 필터를 보존하고, 현재 표만 좁아졌는지 전체 KPI도 좁아졌는지 명시한다.

좁은 화면: KPI 2열, 차트 1열, 필터 줄바꿈. 그래프를 통째로 축소해 축 글씨를 읽을 수 없게 하지 않는다. 표는 자체 가로 스크롤/열 우선순위/목록형 대체 중 데이터에 맞게 고른다. 페이지 전체 가로 넘침은 피한다.

## 글자·표면 규칙

| 역할 | 시작값 | 적용 이유 |
|---|---|---|
| 화면 제목 | Pretendard 28/38px, 700 | 관찰한 상세 제목 역할 재사용 |
| 차트 제목 | 18/26px, 600 | 모든 패널 제목을 크게 만들지 않음 |
| KPI 숫자 | 28~32/38~44px, 700, tabular-nums | 자리수 변화에도 열 정렬 유지 |
| 단위/본문 | 14~16px, 400~500 | 숫자보다 낮은 위계 |
| 축·범례·툴팁 | 축 11~12px, 범례/툴팁 12~13px | 읽기 폭에 맞춰 눈금 수를 줄임 |
| 패널 | 흰 배경, radius 12~16px, 얇은 neutral 선 | 차트가 정보의 중심 |
| 차트 선/격자 | 주선 2~2.5px, 보조선 1~1.5px, 연한 격자 | 값과 기준선을 구분 |

수치는 출발점이다. 원티드 PC의 모든 요소에 똑같은 radius/자간/두께를 적용하지 않는다. UI·SVG/Canvas·툴팁 모두 실제 Pretendard를 로드해야 한다.

## 데이터 인터랙션 계약

- **전역 필터**는 KPI·추이·분포·표를 같은 모집단으로 갱신한다. 로컬 선택(날짜/LOT)은 별도 상태로 두고 적용 범위를 문구/칩으로 표시한다.
- 클릭만으로 정보를 얻도록 하지 않는다. 툴팁과 함께 데이터 표·날짜 선택·기록 상세를 제공한다. 키보드로 같은 기록에 도달할 수 있어야 한다.
- 기간 변경 시 이전 기간도 동일 길이로 이동한다. 비율 차이는 %p, 상대 변화율은 %이며 분모 0이면 '비교 불가'.
- 범례 토글은 '표시만 숨김'인지 '집계에서 제외'인지 구분한다. zoom/brush도 같은 원칙을 적용한다.
- 범위가 바뀌면 페이지 번호를 1로, 더 이상 유효하지 않은 선택을 초기화한다. 날짜를 두 번 필터링해 빈 결과를 만들지 않는다.

## 상태별 UI

| 상태 | 표현 | 피할 표현 |
|---|---|---|
| 최초 로딩 | 패널 크기를 유지하는 skeleton + 상태 텍스트 | 0%를 임시로 표시 |
| 필터 변경 중 | 이전 값 유지 시 갱신 중임을 명시, 완료 후 함께 교체 | 일부 지표만 새 값으로 바뀐 채 기준 시각 유지 |
| 데이터 없음 | 범위와 초기화/조건 변경 행동 | 정상 0건과 미수집을 동일하게 표시 |
| 요청 실패 | 실패한 영역 + 재시도 | 빈 차트를 성공처럼 표시 |
| 부분 결측 | 제외된 표본 수·수집 범위, null gap | 0 대입, 선 연결로 연속 관측인 것처럼 표시 |
| 수집 지연 | 마지막 데이터 시각 + 지연 배지 | 브라우저 현재 시간을 '최근 업데이트'로 표시 |

## 구현 자산

[React starter](../assets/react-starter)는 공식 Montage 4.1.5 + ECharts 6.1.0을 사용한다. `npm ci && npm test && npm run build` 후 `dist/dashboard.html`을 연다. 기존 UI 실험실에는 '데이터·차트' 탭이 추가돼 있다.

- `src/dashboard/Dashboard.jsx`: 전역 필터, KPI, 6종 차트, 기록/상세, 상태 예시.
- `src/dashboard/chart-theme.mjs`, `Chart.jsx`: 재사용 테마·모듈별 import·SVG renderer·ResizeObserver·dispose·표 대체.
- `src/dashboard/data.mjs`: 168개 합성 검사 LOT. 실제 회사 데이터가 아님.
- `src/dashboard/metrics.mjs`: 동일 기간 비교, 가중 비율 집계, histogram, Pareto, CSV.
- `src/dashboard/metrics.test.mjs`: 집계 보존·결측·기간 경계 검증.

불필요한 예제 화면 전체를 새 제품에 복사하지 말고 필요한 차트와 집계 함수를 가져온다. 데이터 계약은 [data-contracts.md](data-contracts.md), 차트 선택/스타일은 [chart-recipes.md](chart-recipes.md)를 읽는다.
