## 필터: 닫힌 버튼만 맞추면 미완성

관찰한 지역 필터의 기준:

- 팝업 폭 560px, 반지름 24px. 국가 Select 높이 48px, 반지름 14px. 내부 폭은 512px(좌우 24px).
- 메뉴는 필드와 같은 폭, 반지름 16px, 가벼운 그림자. 선택 행은 파란 글자와 오른쪽 체크. 네이티브 OS select 메뉴와 다르다.
- 포커스 테두리 `rgba(0,102,255,.43)` 1px + 바깥 `rgba(0,102,255,.12)` 4px. 필드·메뉴·모달의 radius를 하나로 합치지 않는다.
- 국가 선택 후 2열 지역 목록. 상위 지역과 하위 선택 항목을 나누고 각 영역을 스크롤. 선택 수와 삭제 가능한 칩이 표시된다.
- 하단은 작은 초기화 + 넓은 적용 버튼. 서비스 관찰에서 버튼 높이 48px. 공식 Montage 기본 size가 다르면 `size="large"`로 맞춘다.

동작 계약:

1. 모달 열기: `draft = copy(applied)`. 선택을 바꿔도 배경 결과는 유지.
2. 적용: `applied = draft`, 페이지를 1로 이동, 조건에 맞게 결과 계산.
3. 닫기/Escape/바깥 클릭: draft 폐기. 다시 열면 applied를 복원.
4. 초기화: draft만 기본값으로. 칩 삭제·다중 선택·상위 그룹 표시가 같은 상태를 공유.
5. dropdown은 방향키·Enter·Escape, 선택 표시, 포커스 복귀를 확인. 메뉴가 모달 뒤로 숨거나 하단에서 잘리지 않게 portal/overflow를 확인.

React에서는 공식 `Select`/`SelectMultiple`/`Option`을 우선 사용한다. 일반 HTML을 유지해야 하면 접근성이 검증된 기존 컴포넌트를 스타일링한다. 모양만 만든 `div` 옵션이나 키보드 없는 dropdown은 사용하지 않는다.

## 화면 선택표

| 주제/주요 행동 | 기본 구조 | 함께 필요한 상태 |
|---|---|---|
| 설비·재고·데이터 비교 | 검색/필터 + **표** + 상세 | 정렬, 페이지 이동, 행 선택, 일괄 처리, 빈 결과 |
| 예약·신청·등록 | **라벨이 있는 폼** + 요약/CTA | 필수, 설명, 오류, 비활성, 처리 중, 성공 |
| 공고·상품·문서 읽기 | **긴 상세 본문 + 우측 CTA** | 정보 행, 펼치기, 탭, 아코디언, 좁은 화면에서 CTA 재배치 |
| 조직·사용자·팀 소개 | **프로필 헤더 + 설명 + 관련 목록** | 아바타, 배지, 더보기, 팔로우/저장 |
| 탐색·추천·콘텐츠 | 이미지가 필요할 때 카드, 그 외 **텍스트 목록** | 검색, 선택 칩, 다중 필터, 북마크, 스켈레톤 |
| 처리·학습·승인 진행 | **단계 목록 + 진행 표시** | 현재/완료/예정, 다음 행동, 오류/재시도 |

제목만 바꾼 카드 카탈로그를 모든 주제의 결과물로 만들지 않는다. 실제 핵심 행동에 맞춰 위 구조에서 골라 조합한다. 사용자 요청에 필요하지 않은 KPI·배너·소개 패널은 추가하지 않는다.

## 상세 / 폼 실측

공고 상세 제목: 28/700/38px, tracking -0.6608px. 섹션 제목: 22/600/30px, -0.4268px. 작은 제목: 18/600/26px, -0.036px. 우측 액션 패널 340px, 관찰한 sticky top 70px. 모든 제품의 본문을 1400px 꽉 채우지 말고 읽기 폭과 CTA 폭을 구분한다.

OneID 라벨: 14/600/20px. 입력: 48px 높이, 좌우 16px, radius 10px, 글자 16/400. 비활성 CTA: 48px 높이, radius 10px, `#f4f4f5`. **OneID와 Montage Select의 radius는 다르다.** 역할/표면을 구분하며 모든 입력을 같은 규격이라고 하지 않는다.

## 검증할 대표 흐름

최소한 해당 제품에서 쓰는 흐름을 실행한다: 조건 선택→닫기→재열기→적용, 검색→빈 결과→초기화, 행→상세→행동, 필수 누락→오류→수정→제출→결과 반영. 모두 필요한 것은 아니며 사용한 컴포넌트만 확인한다.

폰트 로드 뒤 같은 viewport에서 열림 상태까지 비교한다. 모달 안 메뉴의 portal, 포커스, 스크롤, 모바일 overflow를 특히 확인한다. 기본 상태 스크린샷만으로 완료 판단하지 않는다.
